# 在线漫画只读到章首：修复与清理计划

## 实际证据

- 连接的 iPhone 运行 2.6.7+260910002。18mhx 源的第 2 话缓存只有 1 张图。
- 同一章节 API 实际返回 271 个 img（含 noscript 副本），对应 136 个独立图片地址。
- 旧正文规则 `img@src||img@data-src` 先命中整组 src；除首图外都是 base64 占位，随后 replaceRegex 删除占位，剩下首图。
- 上一轮长图高度限制确有缺陷，但不是这次丢失整章图片的主要原因。

## 修复范围与顺序

1. 用脱敏的首图、懒加载图、noscript 副本复现旧规则漏图，锁住图片顺序和去重。
2. 修正这份用户源配置：正文用 `img@html`，复用现有逐节点图片提取；删除包装 HTML/请求头的 JS、toast 和 base64 替换规则。
3. 不改变全局 `||` 规则语义，不添加站点判断或越过显式选择结果的整页回退。
4. 核对实际整章图片列表，并下载解码首、中、末图片确认源级请求头仍可用。
5. 更新手机的同一源记录；检查书架源快照与错误的单图阅读进度。利用现有包含 sourceConfig 的缓存版本失效，重新打开阅读器。
6. 清理连续阅读器的无效包装方法 `_releaseProvider`、冗余 `_decoded` 标志和重复 mounted 检查。保留每个异步边界的 generation 检查。

## 回退与兼容性分类

- 旧规则整组 `||` 是规则语言契约，应保留；这份源配置的使用方式失效，需要修配置。
- 图片提取器拒绝 data URI 后读取 data-src 是现有受测试的懒加载兼容逻辑，直接复用。
- 原生 ImageDescriptor 与 Web codec 是已确认的平台 API 差异，保留各自释放资源的路径。
- 不改用户的其他源、书架内容或并行工作文件；不新增依赖和 UI。

## 验证

真实章节完整图片列表、首中末解码；漫画规则测试；连续阅读器独立进程测试；格式、静态分析、diff 检查。手机配置回读及重新取章与代码测试分别记录，不用合成测试代替真实书源结果。
